# Разберись — помощник в учёбе

Отдельный сайт для работы с учебным текстом. Три задачи ИИ: объяснить тему, составить тест и разобрать ответ ученика.

## Что работает сразу
- Вставка текста до 20 000 символов и загрузка UTF-8 .txt до 150 КБ с тем же ограничением по символам.
- Учёт числа слов и символов; выбор уровня и цели занятия.
- Подготовка индивидуального запроса для ChatGPT, копирование и переход. Ответ пользователь получает в ChatGPT, это не встроенная генерация.
- Извлечение определений по формату «Термин — определение».
- Локальный тест по минимум трём определениям: до пяти вопросов, варианты ответов, проверка, результат и объяснение ошибки со ссылкой на исходное определение. Это шаблонная самопроверка без модели.
- Скачивание исходного материала в TXT.
- Нет регистрации. Учебный материал не сохраняется постоянно в браузере; перезагрузка возвращает пример.

## ИИ внутри сайта
Серверный код подготовлен, но сервер и API-ключ ещё не настроены. Не заявлять, что на публичном сайте выполняются вызовы модели.

server.mjs вызывает OpenAI Responses API со структурированным JSON-ответом. Ключ только в OPENAI_API_KEY на сервере, не в index.html и не в ai-config.json. Модель по умолчанию gpt-4o-mini, можно задать OPENAI_MODEL. Схема и проверка результата: заголовок, объяснение, тезисы, вопросы, варианты, правильные ответы и обоснования. Число вопросов для режима quiz — пять; правильный ответ обязан входить в варианты.

Для локального запуска нужен Node.js 24: задать переменные окружения по .env.example и выполнить node server.mjs. Сам .env автоматически не читается. Открыть http://127.0.0.1:3000. Для публичной генерации развернуть сервер за HTTPS-прокси и указать адрес /api/study в ai-config.json. ALLOWED_ORIGIN: https://kmaratova674-debug.github.io. GitHub Pages исполняет только клиентскую часть.

Сервер ограничивает размер запросов и частоту. Учебный лимит на один процесс: 5 запросов на IP за 10 минут, 20 суммарно за час; при перезапуске сбрасывается. Для реального открытого сервиса нужны устойчивые лимиты и бюджет в аккаунте провайдера.

## Системный анализ
Проблема: ученику трудно выделить суть материала и понять причину ошибок.
Цель: связать исходный материал, объяснение, проверку знаний и обратную связь.
Роль: ученик. Внешняя система: ИИ-провайдер.
Сущности: материал, цель занятия, уровень, ответ ученика, определение, вопрос, вариант ответа, результат теста, ответ ИИ.
Сценарий: загрузить материал → выбрать цель → получить объяснение/тест/разбор → проверить себя → вернуться к источнику.
Границы: только текст, не OCR/PDF, без школьного журнала и аккаунтов. Оценка локального теста отражает совпадение с исходным определением, а не полноту понимания темы.

## Проверки
Входные данные, ограничения длины, обязательный ответ в режиме разбора, структура теста, правильный ответ среди вариантов, отсутствие ключа, формат API и извлечение определений проверены на локальных тестовых данных. Реальных платных запросов не выполнялось. Ответы ИИ необходимо сверять с учебным материалом.

Документация API: https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses
